# 08 — Project audit (June 2026)

> Snapshot review of the plan + everything committed through `fcd07bc`
> (Phase 0 scaffolding + 4 validated air nodes, no hardware deployed).
> Findings marked **[done]** were addressed in the PR that added this doc;
> the rest are scheduled into the roadmap (`00-architecture.md` §4, §12, §18).

## Verdict

The project is in unusually good shape for its stage. Decisions are recorded
with rationale and rejected alternatives; the naming convention was locked
*before* hardware existed (preventing entity-ID churn, the most painful HA
failure mode); secrets hygiene is clean across all commits; CI gates existed
from day one. The phased plan is ordered sensibly: foundation → first sensor →
surfaces (Apple Home / Grafana) → mesh → automations → resilience → deploy
automation. The gaps below are operational hardening and a few scalability
cliffs expected around 15–30 devices.

## Strengths

- `docs/00-architecture.md` is a genuine living design doc (decision log,
  alternatives pass, honest config-as-code boundary).
- DRY ESPHome fleet (`common/base.yaml` + sensor modules) from node #1.
- Curated allowlists for HomeKit + InfluxDB instead of forward-everything.
- Layered recovery story: git (config) + encrypted backups (runtime state) +
  Proxmox snapshots (host) — with a planned restore drill.
- Per-phase deterministic Definition-of-Done checks (`06-verification.md`).

## Findings

### 1. Monitoring didn't scale and couldn't see itself **[partly done]**
- Stale detection covered only the office node, hand-written per node.
  **[done]** `packages/monitoring.yaml` now derives fleet health from a single
  node list (`sensor.stale_air_nodes` + `binary_sensor.air_fleet_problem`).
- Every alert flows through HA — if HA is down, nothing fires. **Deferred to
  Phase 7:** external dead-man's switch (Healthchecks.io ping, or an Uptime
  Kuma LXC on the Proxmox host probing HA from outside the VM). See §12.

### 2. Allowlist maintenance is a scalability cliff **[decision recorded]**
`packages/influxdb.yaml` / `packages/homekit.yaml` enumerate entities
one-by-one; at the 20–60 device target that's 100+ hand-maintained lines, and
a forgotten entry fails *silently*. Globs (`sensor.*_air_*`) were considered
and **rejected**: they'd sweep in the per-node diagnostics
(`*_air_uptime`, `*_air_wifi_signal`) — exactly the bloat the allowlist
prevents. Decision (§8): keep explicit allowlists, update them in the same PR
as the node (device registry lists expected entities); revisit with a CI
drift check if it gets painful.

### 3. CI version pinning was half-done **[done]**
- HA was pinned (2026.5) but ESPHome floated (`pip install esphome`), so a new
  release could break CI or, worse, pass CI while the older add-on fails.
  **[done]** Both pins now live in `.ha-version` / `.esphome-version`
  (single-sourced; workflows read them).
- No early warning before upgrades. **[done]** `upgrade-canary.yml` runs both
  checks weekly against latest HA/ESPHome; red = fix before upgrading.

### 4. No lint or secret-scanning gate **[done]**
`.gitignore` keeps `secrets.yaml` out of git but nothing caught a token pasted
into a *tracked* file. **[done]** `lint.yml` adds yamllint (`.yamllint.yml`)
+ gitleaks over full history on every PR/push.
**Still open:** enable branch protection on `main` (require the validate +
lint checks) — see `07-github-setup.md`; required before Phase 8 deploys.

### 5. Phase 8 deploy skeleton has known sharp edges **[checklist recorded]**
`deploy.yml` / `scripts/deploy-esphome.sh` stub the health check, don't track
per-node failures in the batch OTA loop, have no automated rollback (docs say
`git revert`; nothing wires it up), and no deploy-failure notification.
Acceptable pre-Phase 8; now captured as a hardening checklist gating
`DEPLOY_ENABLED` (§4).

### 6. Config-mirror drift (minor)
`zigbee2mqtt/configuration.yaml` and `grafana/provisioning/` mirror add-on
config with no sync mechanism yet. Direction of truth is repo → add-on
(`reload-ha.sh` will copy on deploy); until Phase 8 the mirrors are updated by
hand — drift-check them during the Phase 5/4 DoD.
